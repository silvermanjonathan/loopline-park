Chunks explored
Chunk 1 · Your first line

Turn on the gate speaker

Type this one line into your file, exactly as written, and run it.

print("Welcome to Loopline Park!")
Predict Before you run it: what will appear in the output panel? Will the quotation marks be part of it? Say your guess out loud, then run.
The words appear without the quotation marks. The quotes are for Python, not for the guests — they mark where your message starts and ends. Everything between them is called a string.
You should see 
Welcome to Loopline Park!
Chunk 2 · Break it on purposeE5-PRO-TR-?? ⚠

The computer does not guess

Now sabotage your own line. Change print to pint and run it again.

pint("Welcome to Loopline Park!")
Predict Will the computer figure out what you meant, like autocorrect on a phone? What do you think will happen instead?
It refuses. You get an error message called a traceback: 
Traceback (most recent call last):
  File "day1.py", line 1, in <module>
    pint("Welcome to Loopline Park!")
NameError: name 'pint' is not defined

Engineer's rule: read the traceback last line first. It names the problem (pint is not a thing) and the line number where it lives. The computer does only what is written — nothing has ever demanded exactness from you like this before, and that's the whole game.

Chunk 3 · Notes to humans

The # symbol

Fix your line back to print, then add a label above it:

# Gate speaker — plays when the park opens
print("Welcome to Loopline Park!")
Predict Will the line starting with # show up in the output?
No. A line starting with # is a comment — a note for human engineers. Python skips it completely. Real engineers label their work so the next person (or Friday-you) knows what each part does.
Chunk 4 · The marqueeE5-PRO-PD-?? ⚠

Build the entrance marquee

One print() makes one line of output. Stack several to build the big sign, and use comments to label the sections.

# Top border
print("* * * * * * * * * * *")
# Park name
print("   LOOPLINE  PARK")
print("  GATES OPEN TODAY")
# Bottom border
print("* * * * * * * * * * *")
Predict How many lines of output will this program make — four, five, or six?
Four. There are six lines of code, but two are comments, and comments never print. Each print() makes exactly one output line, in the order written — top to bottom, like reading.
You should see 
* * * * * * * * * * *
   LOOPLINE  PARK
  GATES OPEN TODAY
* * * * * * * * * * *
Now make it yours: change the words, add a line, add more border rows.
Chunk 5 · VariablesE5-PRO-VD-?? ⚠

A labeled box that holds a value

The ticket booth needs to remember the price. In Python, = does not mean "equals." It means "gets the value of." Say it out loud: "price gets 20."

price = 20
print(price)
price = 15
print(price)
Predict What two numbers print? And after line 3 runs, is price both 20 and 15?
It prints 20, then 15. A variable is a labeled box holding one value at a time. Line 3 takes the 20 out and puts 15 in — the 20 is gone. That's why = is an action, not a fact. Fill in the first two rows of your trace table for this program: one row per line, tracking what price holds.
You should see
20
15
Chunk 6 · Listening to guests

input() — the booth asks a question

name = input("Welcome! What is your name? ")
print("Hello, " + name + "!")
Predict When you run this, what happens first — does anything print right away? What is the program waiting for?
The question prints, then the program stops and waits. Whatever the guest types gets stored in the box labeled name. The + glues strings together, so the greeting uses whatever name was typed.
You should see 
Welcome! What is your name? Maya
Hello, Maya!
(Your output shows whatever name you typed.)
Chunk 7 · A famous bugE5-PRO-TR-?? ⚠

The '2' + '3' problem

The booth needs to add two numbers a guest types. Try it the obvious way:

a = input("First number? ")
b = input("Second number? ")
print(a + b)
Predict Type 2 and then 3. What will print — 5, or something else?
It prints 23. Here's the rule that explains it: input() always hands back text, even when the guest types digits. So a holds the string "2" and b holds the string "3", and + glues strings together instead of adding. It looks numeric on screen — that's exactly why this bug fools professional engineers too. Try print(type(a)) to see the proof: <class 'str'>.
Chunk 8 · int() at the doorE5-PRO-PD-?? ⚠

Convert, then compute the ticket price

Fix the bug by converting text to a number the moment it arrives — "convert at the door." Then use an f-string to build a tidy receipt: put an f before the quotes, and anything inside { } gets swapped for its value. Keep this tool close: on Friday, three f-strings exactly like this one paint a live roller-coaster dashboard sixty times a second.

name = input("Welcome! What is your name? ")
tickets = int(input("How many tickets? "))
total = tickets * 12
print(f"{name}, {tickets} tickets cost ${total}.")
Predict If the guest is Sam and buys 3 tickets, what exact line prints? Trace it: what does total hold before line 4 runs?
total holds 36 (3 × 12), so it prints Sam, 3 tickets cost $36. The int() wrapper turns the typed "3" into the number 3 before it ever lands in the box — so the math works. Finish your trace table for this program: four lines, four rows.
You should see 
Welcome! What is your name? Sam
How many tickets? 3
Sam, 3 tickets cost $36.
Hinge question · stop here until you're sureE5-PRO-VD-?? ⚠

The two-price ticket

A program runs these two lines, in order: price = 20 and then price = 15.
What does price hold now — 20, 15, both, or 35?

15, and only 15. If you said "both" or "20," re-read Chunk 5 before moving on — everything at the ticket booth (and everything for the rest of camp) depends on this: a variable holds one value, and = replaces it. If you said 15, you're cleared for the build.
Build brief · The Ticket Booth

Your booth, fully staffed

Build a Ticket Booth program that:

1. Greets the park by printing a small marquee (2–3 lines).
2. Asks the guest's name with input().
3. Asks how many tickets they want, converting with int().
4. Computes the total (tickets cost $12) and prints a receipt with an f-string.

Useful pieces: print() · input() · int() · * · f"..." · # comments to label each section.

Suggested start: get the marquee printing first. Then add one question at a time, running after every line you add.

# --- Marquee ---
print("* * * * * * * * *")
print(" LOOPLINE  PARK")
print("* * * * * * * * *")

# --- Ticket booth ---
name = input("Welcome! What is your name? ")
tickets = int(input("How many tickets today? "))
total = tickets * 12
print(f"Enjoy the park, {name}!")
print(f"Receipt: {tickets} tickets = ${total}")
Yours doesn't have to match this — it has to run, and you have to be able to say what each line does.

Choose your exit gate

Floor · approaching the standard

Your marquee prints correctly, and you can break print on purpose and fix it by reading the traceback last line first.

Middle · meets the standard
