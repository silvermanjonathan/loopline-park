Before you build · Two ways to run this lab

pygame if you can. turtle if you can't.

The main build uses pygame, which draws smooth motion at 60 frames a second. It's a real installed package: type pip install pygame in the VS Code terminal. It's also a big compiled package — on a managed school machine that install can need an IT ticket, so put the request in before camp and test it on a real camper machine early in the week.

pygame is not required for this lab. If the install isn't happening, use the turtle edition below. Turtle has been running on every machine since Monday and installs nothing.

What the turtle edition trades away: the train steps from tower to tower instead of gliding — motion is discrete, not continuous — there's no ride clock, and a stalled train freezes at the last safe tower instead of partway up the slope. The four physics lines are identical. The speeds, the heights, the stall: identical. Smoothness is the only casualty.

# ==========================================================
#  LOOPLINE PARK - COASTER SIMULATOR  (turtle edition)
#  Same track, same physics, nothing to install. The train
#  steps from tower to tower instead of gliding.
# ==========================================================

import turtle
import math
import time

# --- YOUR TRACK -------------------------------------------
# Each number is a hill height in meters, left to right.
# Rule 1: the FIRST number is the lift hill. It must be the tallest.
# Rule 2: change these numbers and rerun. That IS the design job.

track = [50, 48, 42, 33, 22, 11, 2, 0, 8, 18, 26, 30, 26, 18, 9, 3, 0]

SEG_LEN = 20          # each hill tower sits 20 meters from the next
GRAVITY = 9.8

# --- SETUP ------------------------------------------------
screen = turtle.Screen()
screen.setup(900, 600)
screen.bgcolor("#1B2951")
screen.title("Loopline Park - Coaster Simulator (turtle)")

step_x = 800 / (len(track) - 1)
scale_y = 400 / max(track)

pen = turtle.Turtle()
pen.hideturtle()
pen.speed(0)
pen.pensize(4)
pen.color("#FCD34D")
pen.penup()
pen.goto(-400, track[0] * scale_y - 250)
pen.pendown()
for i in range(len(track)):
    pen.goto(-400 + i * step_x, track[i] * scale_y - 250)

train = turtle.Turtle()
train.shape("square")
train.color("#DC2626")
train.penup()
train.goto(-400, track[0] * scale_y - 240)

dash = turtle.Turtle()
dash.hideturtle()
dash.penup()
dash.color("#F8FAFC")
dash.goto(-390, 240)

# --- RUN THE RIDE -----------------------------------------
top = track[0]
speed = 2.0
stalled = 0

for i in range(len(track)):
    height = track[i]            # at a tower, the height IS the list number

    # THE PHYSICS: height you have lost becomes speed you have gained
    drop = top - height
    if drop < 0:
        stalled = 1
    else:
        speed = math.sqrt(2 * GRAVITY * drop)
        if speed < 2:
            speed = 2            # the chain lift lets go at 2 m/s

    if stalled == 1:
        dash.clear()
        dash.write("STALLED - hill taller than the lift!", font=("Courier", 18, "bold"))
        break                    # engine word: ends the loop early

    train.goto(-400 + i * step_x, track[i] * scale_y - 240)
    dash.clear()
    dash.write(f"SPEED {speed * 2.24:.0f} mph    HEIGHT {height:.0f} m", font=("Courier", 16, "bold"))
    time.sleep(SEG_LEN / speed / 4)

turtle.done()
You should see Yellow rails on navy. A red square that hops tower to tower — a long pause at the crest while the chain lets go, then quicker and quicker hops toward the bottom. The whole ride takes about six seconds of watching, with the dashboard updating at every tower.
01

The ride with no engine

Before any code: what is a roller coaster, mechanically? Answer this one right and the whole simulator makes sense.

Unplugged · Count the engines

Clack, clack, clack… and then what?

The Comet's chain drags the train up the lift hill — that's the clack clack clack you hear — and at the crest, the chain lets go. The train still has the entire ride ahead of it: drops, climbs, curves, the run into the station.

Predict From the moment the chain lets go to the moment the ride ends: how many motors push the train? Zero — one at the bottom of each drop — or one big one under the station? Say your answer out loud before you tap.
Zero. A gravity coaster is a savings account. The chain makes exactly one deposit — the height of the lift hill — and the entire ride is spending it. Rolling down converts height into speed. Climbing back up converts speed back into height. That trade, in both directions, is the whole machine, and today you'll write it in one line of Python. Say the sentence of the day out loud, because you'll use it all afternoon: height you have lost becomes speed you have gained.

Chunk 03 — Where is the train?E5-PRO-VD-?? ⚠

Between two towers

The train's position is measured in meters along the track — not in tower numbers. The engine has to work out which two towers the train is between, and how high the rail is right there. Type this experiment and run it (keep your Chunk-01 track and SEG_LEN lines above it):

position = 70.0

seg = int(position / SEG_LEN)
frac = (position - seg * SEG_LEN) / SEG_LEN
height = track[seg] + (track[seg + 1] - track[seg]) * frac

print(seg)
print(frac)
print(height)
Predict 70 ÷ 20 is 3.5. So does seg print 3.5, 3, or 4? And once you've committed to seg, what is frac? Say both before you run.

seg is 3 — int() chops the decimals off, always downward, never rounding up. New job for an old friend: on Monday int() converted a guest's typed text at the door; here it chops 3.5 down to 3. So the train is between tower 3 and tower 4, and frac is 0.5 — exactly halfway across that gap. frac is always between 0 and 1: 0 means “at the left tower,” 1 means “at the right tower.”

Then the height line blends the two towers: tower 3 is 33 m, tower 4 is 22 m, so crossing that gap the rail falls 11 m. Halfway across, you've fallen half of it: 33 + (22 − 33) × 0.5 = 27.5. Read the line as: start at the left tower's height, add frac's share of the difference. This is the first of the four physics lines, and it answers one question: how high is the rail exactly where the train is?

Chunk 04 — Height lost becomes speed gainedE5-PRO-RD-?? ⚠

The one-line trade

Here it is: the sentence of the day, written in Python. drop is how far below the lift hill's top the train has come — the height it has spent so far. Type this experiment and run it three times.

import math

GRAVITY = 9.8

drop = 20
speed = math.sqrt(2 * GRAVITY * drop)
print(f"{speed * 2.24:.0f} mph")
Predict — this one surprises almost everyone With drop = 20 this prints 44 mph. Now change it to 40 — exactly double the drop. Commit before you run: does the speed double to 88? Then try 80.

63, not 88. And 80 m of drop gives 89, not 176. Climb the ladder: 20 → 44 mph, 40 → 63 mph, 80 → 89 mph. Every doubling of the drop multiplies the speed by about 1.4 — that's what a square root does to a doubling. To truly double a coaster's speed, you need four times the drop. Now you know why nobody builds them that way.

You don't need to know where 2 × gravity × drop comes from — that proof lives in high school. What you need is the feel of it, and you just got that in three runs. (The 2.24 converts meters-per-second into miles-per-hour, because dashboards speak mph.)

In the real engine, nobody types drop in — it's measured from your track, every frame:

top = track[0]
drop = top - height

The lift hill is the savings account. drop is how much has been withdrawn so far.

Chunk 05 — Move by however fast you are goingE5-PRO-RD-?? ⚠

The line that makes it a simulation

Now the engine, for real. The ride runs inside one counted loop — 60 frames a second, up to 3000 frames, which is a 50-second limit: the park closes whether your train is done or not. (A finished ride leaves early — Chunk 08.) Inside the loop, after the height and speed are found, one line moves the train:

FPS = 60
DT = 1.0 / FPS        # how much time passes in one frame

for frame in range(3000):
    pygame.event.pump()              # keeps the window alive

    # ... Chunk 03 finds height ... Chunk 04 finds speed ...

    position = position + speed * DT
Predict Read the last line out loud the Monday way: “position gets…” Then: at 4 mph (2 m/s), how many meters is one frame's step? At 70 mph (31 m/s)? Last — find the line in this program that says “speed up at the bottom of the hill.”

“Position gets its old value, plus one frame's step: speed times DT.” At 2 m/s that step is 2 × 1⁄60 ≈ 0.03 m — a fingernail. At 31 m/s it's about half a meter — every sixtieth of a second.

And you can stop looking: there is no line that says speed up. Nothing in this program schedules the rush at the bottom. Chunk 04's line hands this line a bigger speed, so this line takes a bigger step, and the rushing emerges. That is the entire difference between an animation — a script that says where to be — and a simulation: a rule that decides what happens next. The whole loop is one sentence, sixty times a second: move forward by however fast you are going.

Chunk 06 — The push at the top

Why the engine has a speed floor

Two small lines sit right under the speed line. They look like decoration. They are not.

speed = math.sqrt(2 * GRAVITY * drop)
if speed < 2:
    speed = 2                # the chain lift lets go at 2 m/s
Predict At the very top of the lift hill, height equals top, so drop is 0. What is math.sqrt(0)? And if speed were allowed to keep that value, what would Chunk 05's position line do — frame after frame, forever?
math.sqrt(0) is 0. A speed of 0 means a step of 0, which means a train parked at the crest of its own ride — no error, no traceback, just a red rectangle sitting at the top for the full 50 seconds. Silence is not the same as “no bug”; Wednesday's uncalled stamp taught you that. These two lines are the chain lift's final shove: the train is never allowed below 2 m/s — about 4 mph, the exact creeping crawl you feel at the top of a real lift hill, right before everything happens.
Chunk 07 — The inspector's lines

The one thing square roots refuse to do

First, a dare. In your scratch file, run this single line:

print(math.sqrt(-1))

It refuses — and now look at how the engine wraps its own square root. Read this slowly:

drop = top - height
if drop < 0:
    stalled = 1
else:
    speed = math.sqrt(2 * GRAVITY * drop)
    if speed < 2:
        speed = 2

# ... and further down, the only gate that lets the train move:

if stalled == 0:
    position = position + speed * DT

Read the traceback last line first, Monday's rule: ValueError: math domain error. “Domain” is math-speak for “that number is not allowed in here.” Square roots do not do negatives — ever.

So the engine posts an inspector at the door. if drop < 0: don't touch the math at all — set stalled to 1 instead. (stalled is the engine's light switch: 0 means running, 1 means frozen.) Only one of the two branches runs, Tuesday's fork. And at the bottom, if stalled == 0 — that's == asking, not = assigning — is the single gate that lets the train move. Once stalled becomes 1, nothing moves again, and a red STALLED banner comes up for the rest of the run.

On the track you've been given, drop never goes below zero. So here is the question this chunk refuses to answer: when would it? What would the train have to be doing? Hold that exact question in your hands — Section 04 makes you commit to an answer.

# ==========================================================
#  LOOPLINE PARK - COASTER SIMULATOR  (pygame edition)
#  Design a track. Watch the physics run it. 60 frames a second.
# ==========================================================

import pygame
import math

# --- YOUR TRACK -------------------------------------------
# Each number is a hill height in meters, left to right.
# Rule 1: the FIRST number is the lift hill. It must be the tallest.
# Rule 2: change these numbers and rerun. That IS the design job.

track = [50, 48, 42, 33, 22, 11, 2, 0, 8, 18, 26, 30, 26, 18, 9, 3, 0]

SEG_LEN = 20          # each hill tower sits 20 meters from the next
GRAVITY = 9.8
FPS = 60
DT = 1.0 / FPS        # how much time passes in one frame

# --- COLORS (Loopline Park) -------------------------------
NAVY = (27, 41, 81)
YELLOW = (252, 211, 77)
RED = (220, 38, 38)
CREAM = (248, 250, 252)
GREEN = (16, 185, 129)

# --- SETUP ------------------------------------------------
pygame.init()
screen = pygame.display.set_mode((900, 600))
pygame.display.set_caption("Loopline Park - Coaster Simulator")
clock = pygame.time.Clock()
big = pygame.font.SysFont("couriernew", 30, bold=True)
small = pygame.font.SysFont("couriernew", 18)

# --- TURNING A HILL HEIGHT INTO A SCREEN SPOT -------------
tallest = max(track)
step_x = 800 / (len(track) - 1)
scale_y = 400 / tallest

rail_points = []
for i in range(len(track)):
    x = 50 + i * step_x
    y = 550 - track[i] * scale_y
    rail_points.append((x, y))

# --- RUN THE RIDE -----------------------------------------
top = track[0]
position = 0.0                       # how many meters along the track we are
track_length = (len(track) - 1) * SEG_LEN
speed = 2.0
stalled = 0

for frame in range(3000):
    pygame.event.pump()              # keeps the window alive

    # WHERE ARE WE? -- find the two towers we are between
    seg = int(position / SEG_LEN)
    if seg > len(track) - 2:
        seg = len(track) - 2
    frac = (position - seg * SEG_LEN) / SEG_LEN

    # our height is part way between those two towers
    height = track[seg] + (track[seg + 1] - track[seg]) * frac

    # THE PHYSICS: height you have lost becomes speed you have gained
    drop = top - height
    if drop < 0:
        stalled = 1
    else:
        speed = math.sqrt(2 * GRAVITY * drop)
        if speed < 2:
            speed = 2                # the chain lift lets go at 2 m/s

    # move forward by however fast we are going
    if stalled == 0:
        position = position + speed * DT

    # --- DRAW -------------------------------------------------
    screen.fill(NAVY)
    pygame.draw.line(screen, GREEN, (50, 550), (850, 550), 3)
    pygame.draw.lines(screen, YELLOW, False, rail_points, 4)

    # support towers under each hill
    for i in range(len(track)):
        pygame.draw.line(screen, (60, 80, 130),
                         (rail_points[i][0], rail_points[i][1]),
                         (rail_points[i][0], 550), 2)

    # the train
    tx = 50 + (position / SEG_LEN) * step_x
    ty = 550 - height * scale_y
    pygame.draw.rect(screen, RED, (tx - 16, ty - 14, 32, 14), border_radius=4)

    # the dashboard
    screen.blit(big.render(f"SPEED  {speed * 2.24:.0f} mph", True, CREAM), (50, 30))
    screen.blit(small.render(f"HEIGHT {height:.0f} m", True, CREAM), (50, 70))
    screen.blit(small.render(f"TIME   {frame * DT:.1f} s", True, CREAM), (50, 92))

    if stalled == 1:
        screen.blit(big.render("STALLED - hill taller than the lift!", True, RED), (50, 500))

    pygame.display.flip()
    clock.tick(FPS)

    if position >= track_length:
        break

pygame.time.wait(3000)
pygame.quit()

Broken Coaster 01

The ride that froze at 153 meters

Symptom: the train runs beautifully, starts climbing the big late hill, then freezes partway up the slope with the STALLED banner. Nothing below the track line was touched.

track = [50, 48, 40, 25, 10, 0, 20, 40, 55, 40, 20, 0]

Bug: the 55 — a hill taller than the 50 m lift hill.

Why it happens: by 50 m up that hill, the train has traded back every meter of height it started with. The savings account reads zero with 5 m of hill still to climb; on the very next frame drop goes negative, the inspector fires, and stalled gets 1 — your Section-04 answer, live, at position 153 m.

Fix: any value under 50. Change the 55 to 45 and the same layout completes in about 17 seconds.

        position = speed * DT

Bug: the position line lost its position +. It now reads “position gets just this frame's step.”

Why it happens: Monday's rule, with teeth: = replaces what's in the box — it never adds to it. Every frame, all the meters the train had covered get crossed out and replaced with one fresh 3-centimeter step from the start line. The train is placed at the gate, sixty times a second, forever.

Fix: carry the old value along — position = position + speed * DT. “Position gets its old self, plus a step.”

Broken Coaster 03

Parked at the summit

Symptom: the train sits at the very top of the lift hill, dashboard reading SPEED 0 mph, for 50 silent seconds. No error anywhere.

    drop = top - height
    speed = math.sqrt(2 * GRAVITY * drop)

    if stalled == 0:
        position = position + speed * DT

Bug: the speed floor is gone — the two if speed < 2 lines were deleted.

Why it happens: at the crest, drop is 0, so math.sqrt(0) is 0, so the step is 0 meters — and a train that never moves never gets a drop to spend. It looked like those two lines were decoration; they're the chain's last shove over the top. Silence, not a traceback — the same trap as Wednesday's uncalled stamp.

Fix: restore the floor under the sqrt line: if speed < 2: then speed = 2.

Broken Coaster 05

The one-word crash

Symptom: instant traceback on the first frame — and yes, import math is right there at the top of the file.

import math

# ...

        speed = sqrt(2 * GRAVITY * drop)

  File "coaster.py", line 71, in <module>
    speed = sqrt(2 * GRAVITY * drop)
NameError: name 'sqrt' is not defined

Bug: sqrt's full name is math.sqrt — this line tore the address off.

Why it happens: import math carries the toolbox into the room; you still have to say which drawer. On its own, sqrt names nothing, and the computer does not guess — the oldest rule in camp. Read the traceback last line first: NameError, the same species as Monday's pint.

Fix: speed = math.sqrt(2 * GRAVITY * drop) — the physics line, with its address restored.

import math

# TODO 2 (after your first good run): copy your Version 1 list into
#         the comment below, then change at least three numbers with
#         a goal in mind, and rerun. Keep both versions.
# V1:
# What changed and why:

# TODO 3 (stretch, from the exit gates): teach the engine friction.

SEG_LEN = 20          # each hill tower sits 20 meters from the next
GRAVITY = 9.8
FPS = 60
DT = 1.0 / FPS        # how much time passes in one frame

# --- COLORS (Loopline Park) -------------------------------
NAVY = (27, 41, 81)
YELLOW = (252, 211, 77)
RED = (220, 38, 38)
CREAM = (248, 250, 252)
GREEN = (16, 185, 129)

# --- SETUP ------------------------------------------------
pygame.init()
screen = pygame.display.set_mode((900, 600))
pygame.display.set_caption("Loopline Park - Coaster Simulator")
clock = pygame.time.Clock()
big = pygame.font.SysFont("couriernew", 30, bold=True)
small = pygame.font.SysFont("couriernew", 18)

# --- TURNING A HILL HEIGHT INTO A SCREEN SPOT -------------
tallest = max(track)
step_x = 800 / (len(track) - 1)
scale_y = 400 / tallest

rail_points = []
for i in range(len(track)):
    x = 50 + i * step_x
    y = 550 - track[i] * scale_y
    rail_points.append((x, y))

# --- RUN THE RIDE -----------------------------------------
top = track[0]
position = 0.0                       # how many meters along the track we are
track_length = (len(track) - 1) * SEG_LEN
speed = 2.0
stalled = 0

for frame in range(3000):
    pygame.event.pump()              # keeps the window alive

    # WHERE ARE WE? -- find the two towers we are between
    seg = int(position / SEG_LEN)
    if seg > len(track) - 2:
        seg = len(track) - 2
    frac = (position - seg * SEG_LEN) / SEG_LEN

    # our height is part way between those two towers
    height = track[seg] + (track[seg + 1] - track[seg]) * frac

    # THE PHYSICS: height you have lost becomes speed you have gained
    drop = top - height
    if drop < 0:
        stalled = 1
    else:
        speed = math.sqrt(2 * GRAVITY * drop)
        if speed < 2:
            speed = 2                # the chain lift lets go at 2 m/s

    # move forward by however fast we are going
    if stalled == 0:
        position = position + speed * DT

    # --- DRAW -------------------------------------------------
    screen.fill(NAVY)
    pygame.draw.line(screen, GREEN, (50, 550), (850, 550), 3)
    pygame.draw.lines(screen, YELLOW, False, rail_points, 4)

    # support towers under each hill
    for i in range(len(track)):
        pygame.draw.line(screen, (60, 80, 130),
                         (rail_points[i][0], rail_points[i][1]),
                         (rail_points[i][0], 550), 2)

    # the train
    tx = 50 + (position / SEG_LEN) * step_x
    ty = 550 - height * scale_y
    pygame.draw.rect(screen, RED, (tx - 16, ty - 14, 32, 14), border_radius=4)

    # the dashboard
    screen.blit(big.render(f"SPEED  {speed * 2.24:.0f} mph", True, CREAM), (50, 30))
    screen.blit(small.render(f"HEIGHT {height:.0f} m", True, CREAM), (50, 70))
    screen.blit(small.render(f"TIME   {frame * DT:.1f} s", True, CREAM), (50, 92))

    if stalled == 1:
        screen.blit(big.render("STALLED - hill taller than the lift!", True, RED), (50, 500))

    pygame.display.flip()
    clock.tick(FPS)

    if position >= track_length:
        break

pygame.time.wait(3000)
pygame.quit()

What this simulator ignores

Every model leaves things out — good engineers say which

Friction. This train returns to full speed in every valley, forever. A real train pays a tax on every meter travelled — which is exactly the 4 mph gap you caught at Fury 325. The stretch exit gate is where you build the tax collector.

Straight rails. Every gap between towers is a straight slope. No loops, no banking, no g-forces pressing you into your seat — the parts of coaster engineering that need real algebra and beyond. This lab runs on one square root, on purpose.

Gravity only. The savings-account rule — the first hill pays for everything — holds for chain-lift coasters. Launched coasters (magnets, catapults) add energy mid-ride and break "no hill taller than the first" completely. Question for the walk home: would our STALLED inspector make any sense on a launched ride?

Stretch · exceeds the standard

Teach the engine friction. Change the drop line to drop = top - height - position * 0.01 and rerun: the stock ride's top speed dips from 70 to 69 mph and it runs a touch longer. Then build a 99 m Fury-style lift hill and raise the 0.01 until the predicted top speed lands on the real ride's 95 mph — the honest number is up near 0.08. Say out loud where the missing speed physically went. (Fair warning: with friction on, a late hill your track barely cleared can now stall, exactly like a real train rolling back — your inspector already knows what to do.
