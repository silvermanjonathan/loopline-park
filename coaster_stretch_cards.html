The Shelf Gets Taller

Today the shelf meets Friday's headliner: the roller-coaster simulator. Its entire track is one list — today's shelf, wearing meters.

Experiment 1 · seventeen numbers, one roller coaster

Type this in a scratch file. Do not run it yet.

track = [50, 48, 42, 33, 22, 11, 2, 0, 8, 18, 26, 30, 26, 18, 9, 3, 0]

SEG_LEN = 20   # each hill tower sits 20 meters from the next

print(len(track))
print(track[0])
print(track[7])
Predict — in pencil, before you run Each number is one support tower's height in meters, left to right.
print(len(track)) →    print(track[0]) →    print(track[7]) →
Now run it — you should see 
17
50
0
The list is the shelf; the index picks the ride. track[0] is the first spot — the 50 m lift hill. track[7] is the eighth tower: ground level, the bottom of the big drop. And with 17 towers, the last one is track[16] — count and last spot are one apart. Today's rule, now load-bearing: get it wrong on a coaster and the crash is real.
Experiment 2 · where is the train?

Keep your track lines. Add this below them.

position = 70.0

seg = int(position / SEG_LEN)
frac = (position - seg * SEG_LEN) / SEG_LEN
height = track[seg] + (track[seg + 1] - track[seg]) * frac

print(seg)
print(frac)
print(height)
Predict — commit before you run The train is 70 meters along the track, and 70 ÷ 20 is 3.5. So does seg print 3.5, 3, or 4? Circle one. Then: frac →
Now run it — you should see 
3
0.5
27.5
int() chops the decimals off — always downward. Monday it converted a guest's typing at the door; here it chops 3.5 to 3, so the train is between tower 3 and tower 4, exactly halfway (frac is 0.5). Then the height line blends the two shelves: start at tower 3's height (33), add half the difference to tower 4 (22) — that's 27.5. This exact line tells the train how high it is, sixty times every second. Friday, you run the whole ride.

The Speed of Falling

Here is the single line of physics that powers Friday's roller coaster — and it surprises almost everyone.

The experiment · height lost becomes speed gained

Type this in a scratch file. Run it three times.

import math

GRAVITY = 9.8

drop = 20
speed = math.sqrt(2 * GRAVITY * drop)
print(f"{speed * 2.24:.0f} mph")
Two new pieces, both small. math.sqrt() takes a square root; it lives in the math toolbox, so import math carries the toolbox in and math.sqrt names the drawer — the same pattern as yesterday's random.choice. And the :.0f inside the f-string is a rounding dial: whole numbers only. (The 2.24 converts meters-per-second into mph, because dashboards speak mph.)
Predict — commit in pencil first drop is how far the coaster has fallen below its lift hill. With drop = 20 this prints 44 mph. Now change it to 40 — exactly double the fall. Your guess before running: mph. (Does doubling the drop double the speed to 88?) Then try 80: mph.
Now run it — you should see 
44 mph
63 mph
89 mph
63, not 88. Climb the ladder: 20 → 44, 40 → 63, 80 → 89. Every doubling of the drop multiplies the speed by about 1.4 — that's what a square root does to a doubling. To truly double a coaster's speed you need four times the drop. Now you know why nobody builds them that way.
Reality check · Fury 325, Carowinds

Test your one line against a real ride

Fury 325's lift hill is 99 meters — the tallest chain-lift coaster in the world. Set drop = 99 and run.

Predict, run, then think Your program prints mph. The real Fury 325 tops out at 95 mph. Your line is off by only a few mph — but always in the same direction: too fast. One sentence — where does the missing speed go on the real ride?
Check yourself It prints 99 mph — 4 mph hot. The missing speed leaks away as friction in the wheels and air pushing back on the train: every rattle and roar a coaster makes is energy that used to be speed. Your one line of Python landed within 4 mph of a thirty-million-dollar machine, and you can say exactly why it missed. That's the whole job of an engineer. Friday, this line powers a ride you design yourself.
