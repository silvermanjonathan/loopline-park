What a trace table does: it lets you run a program with a pencil instead of a computer.
  1. One row for every line of code, in the order Python runs them.
  2. One column for every variable in the program.
  3. After each line, write what each variable holds right now.
  4. If a line changes a variable, cross out the old value and write the new one beside it. Never erase — the crossing-out is the point.
Worked example · done for you

The two-price ticket

#Codeprice variableOutput
1price = 2020—
2print(price)2020
3price = 1520  15—
4print(price)1515
Look hard at line 3. The 20 gets crossed out. A variable is a labeled box that holds one value at a time, and = means gets, not equals. After line 3 the price is 15 — not 20, not both, not 35.
Grid A · your turn

The Ticket Booth

A guest named Sam buys 3 tickets. Trace it. Put a dash in any box that has nothing in it yet.

#CodenameticketstotalOutput
1name = input("...name? ")
2tickets = int(input("...? "))
3total = tickets * 12
4print(f"{name}, {tickets} tickets cost ${total}.")
Line 1: name = Sam · tickets — · total — · output: the question, then it waits.
Line 2: name = Sam · tickets = 3 · total — · output: the question, then it waits.
Line 3: name = Sam · tickets = 3 · total = 36 · no output — this line only does math.
Line 4: nothing changes · output: Sam, 3 tickets cost $36.
Two things to check on yourself: tickets holds the number 3, not the text "3", because int() converted it at the door. And total is empty until line 3 runs — a variable doesn't exist before the line that makes it.
